Stage by stage

1 Schedule

main.py uses APScheduler base cron at 10:00, 12:00, 14:00, and 15:30 ET (Mon–Fri), ±60 s jitter. Set SCHEDULE_EXTRA_ENABLE to add more ET times from SCHEDULE_EXTRA_SLOTS (default 11:30,13:30). is_us_equity_rth gates run_cycle to NYSE Mon–Fri 09:30–16:00 ET, minus a built-in holiday list (and NYSE_HOLIDAYS). Each finished cycle logs cycle_summary JSON (includes compact market_regime); optional TRADING_METRICS_JSONL_PATH appends the same payload to a file.

Position health — POSITION_HEALTH_INTERVAL_MIN (default 5 min; set to 0 to disable) runs run_position_health during RTH. It logs all open positions and fires rule-based trail giveback exits: if unrealized P&L has given back more than TRAIL_GIVEBACK_PCT (default 40 %) of the tracked peak (multi-day unless TRAIL_RESET_DAILY), it executes a SELL via executor.execute — no LLM. State is persisted in the position_trail_state SQLite table. The same job runs expiry sweep and profit-ladder partial closes on options. Whenever one of those paths places an order, the bot also writes a normal trades / JSONL journal row (same shape as scan-cycle rows): rationale ends with _automation and logic_json.automated_exit.kind is trail_giveback, profit_ladder, or expiry_sweep, so weekly review and greps can tell a programmed take-profit / risk exit from a model-driven SELL. Separately, GTC stock bracket take-profit (limit) and stop-loss (stop) legs fill at Alpaca with their own order IDs; each health tick calls sync_bracket_exit_fills to poll recent closed SELLs and append the same journal shape when order_id is not already in trades (bracket_take_profit / bracket_stop; disable with BRACKET_FILL_SYNC_DISABLE).

EOD summary — run_eod_summary runs at 16:05 ET (Mon–Fri, ±30 s). No LLM. Queries today's journal rows and live Alpaca account, then writes data/reports/LATEST_EOD.md and a dated eod-YYYY-MM-DD.md for the dashboard and any ad-hoc reader.

2 Watchlist

watchlist.py calls Alpaca's screener for most-actives by volume, keeps the top WATCHLIST_SCREENER_SIZE symbols after quality filters (default 20; legacy WATCHLIST_SIZE applies when WATCHLIST_SCREENER_SIZE is unset), prepends regime anchors (SPY,QQQ), optionally merges bearish hedge tickers from get_market_regime() when conviction ≥ REGIME_BEARISH_INJECT_THRESHOLD (skipped when TRADING_WATCHLIST static override is set), then appends every open-position underlying when WATCHLIST_INCLUDE_OPEN_POSITIONS=true (default) — held names are never capped or dropped for space. TTL-cached for WATCHLIST_TTL_SEC with a cache key that includes the regime fingerprint. WATCHLIST_DISABLE falls back to anchors only; TRADING_WATCHLIST static override wins. Optional post-filters: WATCHLIST_DENY_SYMBOLS / WATCHLIST_DENY_PREFIXES, WATCHLIST_MAX_SPREAD_PCT, WATCHLIST_MIN_MARKET_CAP / WATCHLIST_MIN_AVG_DOLLAR_VOL (yfinance, cached). WATCHLIST_ENFORCE_MIN_PRICE defaults to true and drops symbols whose Alpaca last trade is below WATCHLIST_MIN_PRICE (default $5) — keeps the brain off penny stocks where ATR exceeds price and bracket orders cannot be priced. Set WATCHLIST_ENFORCE_MIN_PRICE=false to opt back in.

3 Snapshot

data_feed.get_market_snapshot loads about 120 trading days of daily OHLCV from Alpaca (IEX), runs indicators.add_indicators (pure pandas math — not pandas-ta), then folds in the Alpaca stock snapshot when available: latest trade (or minute/daily bar) for live price, daily bar VWAP and volume, and previous close for change_pct.

Per-symbol technicals exposed under indicators (last bar, rounded for the model):

  • rsi_14 — 14-period RSI-style oscillator (smoothed average gain vs loss on closes).
  • macd / macd_signal — MACD line (EMA12 − EMA26) and 9-period signal EMA of that line.
  • ema_20 / ema_50 — Close EMAs for short vs medium trend.
  • atr_14 — Average True Range (14), used downstream for bracket distances and volatility context.
  • adx_14 — Trend strength 0–100-ish (weak trend vs strong).
  • stoch_rsi_k / stoch_rsi_d — Stochastic RSI (14) and a 3-bar SMA of k (momentum within RSI range).
  • obv — On-balance volume cumulative series (directional volume pressure).
  • bb_upper / bb_lower — Bollinger bands, 20-day SMA ± 2σ on closes.
  • volume_ratio — Today’s volume vs a 20-day volume moving average (relative participation).
  • vwap, volume, prev_close, change_pct, daily_bar_close — session / prior-day context from the snapshot pipeline.

Account & position (Alpaca trading API, same dict): account.equity, cash, daily_pnl (vs last_equity), open_positions, daytrade_count, pattern_day_trader. position is either held: false or held with qty, avg_entry, unrealized_pnl / unrealized_pct, market_value, current_price. portfolio_context lists all open positions; when sector lookup is on, sector_notional_pct summarizes exposure by sector. market_regime (when present) repeats the cycle-level pre-brain verdict: direction, conviction, rationale — identical on every symbol row in that scan. data_quality flags missing critical fields vs optional enrichers; symbol_sector labels the scanned equity (yfinance). SECTOR_LOOKUP_DISABLE=true skips sector fetches.

4 Enrich

Everything below is best-effort: TTL caches, graceful omission if a key is missing or an env disables a layer (MACRO_DISABLE, ENRICHMENT_DISABLE, OPTIONS_SNAPSHOT_DISABLE, etc.).

  • Earnings & headlines — yfinance → earnings_days_away, next_earnings_date. RSS bundle → filtered news_headlines (and optional news_feed_errors); news_sentiment is see_headlines when titles exist.
  • FRED macro (needs FRED_API_KEY) → macro: dgs10, dgs2, t10y2y (10y−2y spread), unrate, cpi_yoy.
  • VIX — vix.level, change_pct, regime (calm / normal / elevated / stress) from recent ^VIX closes.
  • CNN Fear & Greed — fear_greed.score, rating, prior close / 1w reference fields when returned. Feeds the regime engine's early-warning signals.
  • Finnhub (API key) — earnings_calendar (global) and analyst_recommendation (per symbol) when each call succeeds.
  • Options — options: nearest listed expiry, atm_strike, atm.call / atm.put with iv, mid, bid, ask when chain data exists; strikes_ring repeats that for ATM ± configured strikes.

The merged object is what the brain and risk_engine see; the journal’s logic_json excerpt keeps the same high-signal keys for audit (including market_regime when present).

5 Brain

claude_brain.get_decision runs a single Haiku call (BRAIN_TRADER_MODEL) and returns structured JSON. The system prompt is directional momentum (bullish and bearish playbooks; uses market_regime when the snapshot includes it). The journal stores debate with mode (e.g. single_trader_haiku) and the raw trader pitch. Deterministic gates that previously justified a second model — earnings proximity, RSI extreme without ADX trend, IV-rank size haircut — now live in risk_engine.validate.

Parse robustness: when Claude returns prose without a JSON object, _call_and_parse retries up to twice (reminder, then final-strict mode with bumped max_tokens) before raising a typed _ModelParseError. get_decision converts that into a deterministic safe-HOLD shell (_parse_fallback=true) so one symbol's flaky response can never halt the rest of the cycle. Logs WARNING trader_parse_fallback with a 240-char snippet for ops visibility.

Both personas get the same snapshot JSON; the system prompt spells out how to use it — e.g. require price + indicator alignment on the underlying before BUY/SELL, align with market_regime when present, force HOLD when data_quality.missing_critical is non-empty, treat macro/VIX/Fear & Greed/Finnhub/options as supporting context only, respect earnings_days_away for event risk, and prefer options vs stock when ADX/StochRSI line up and vix.regime is calm/normal. risk_engine still enforces tier-1 kill-switches and tier-2 policy (see step 6).

6 Risk

risk_engine.validate runs after the brain. Tier 1 (always on): invalid equity; daily loss and peak drawdown HALT; broken options fields; symbol/strategy allowlists. Tier 2: confidence floor (default MIN_CONFIDENCE); optional RISK_VIX_REGIME_CONFIDENCE=true raises/lowers that floor by vix.regime; optional RISK_VIX_REGIME_COOLDOWN=true scales post-SELL cooldown via COOLDOWN_MULT_*; concurrent BUY cap; Alpaca daytrade_count vs PDT_DAYTRADE_CEILING when equity < PDT_EQUITY_FLOOR; size_pct clamp to MAX_POSITION_PCT; sector caps (MAX_SECTOR_NOTIONAL_PCT and MAX_UNKNOWN_SECTOR_PCT); earnings blackout; RSI+ADX chop filter; IV-rank half-size; minimum option DTE; overnight hold on discretionary SELL unless risk_exit_kind is an automation bypass; intraday giveback halt for new BUYs after a large session peak fades.

MAX_ADD_TO_POSITION (default off) — a BUY on an already-held long_stock symbol is forced HOLD unless this env is true.

OPTIONS_MIN_HOLD_HOURS (default 0.5 h) — evaluated before overnight hold: SELL on long_call / long_put is blocked until the position has been held this long. Bypass: if unrealized_pct ≥ PROFIT_LOCK_PCT (default 20 %), min-hold and same-day overnight hold for options are waived and a risk_warnings note is logged.

RISK_SOFT_POLICY=true turns some Tier-2 blocks into risk_warnings only (still logs) — use for paper experiments, not as a substitute for capital limits.

7 Execute

Only BUY/SELL reach executor.execute. Stock buys go out as GTC bracket orders with stops/take-profits ATR-clamped (ATR_MULTIPLIER_STOP/TP); when the ATR floor would produce a non-positive stop (sub-dollar names like EZGO where ref - ATR < 0), _clamp_bracket_prices returns None and the caller skips with atr_clamp_infeasible_stop_tp rather than letting a negative stop reach Alpaca. Stock sells are simple DAY market exits — never with stop_loss / take_profit fields attached. Long calls/puts: contract count is min(budget from size_pct, conviction_contract_cap(confidence)) where the cap comes from OPTIONS_SIZE_TIERS (default 0.70:2,0.78:3), clamped by MAX_OPTIONS_CONTRACTS_HARD, with MAX_OPTIONS_CONTRACTS as the floor when below all tiers or tiers disabled. logic_json.execute records option_qty and conviction_contract_cap on fills.

Option liquidity gate (OPTIONS_REQUIRE_BID=true default): before submitting either side of a long_call/long_put, options_exec.fetch_option_bid_ask is consulted. BUY requires bid > 0 AND ask > 0 (rejection: option_no_bid_at_buy) — prevents opening dormant contracts that have an ask but no buyer (FNDX-class). SELL requires bid > 0 (rejection: option_no_bid_for_market_sell) — avoids the wasted Alpaca round-trip and the 40310000 error-spam loop; position remains open and retries naturally when a real bid reappears.

8 Journal & ping

journal.write_journal_entry bundles snapshot excerpt (including data_quality, market_regime, and sector hints) + raw decision + final decision + execute result into logic_json and writes one row to SQLite (trades) plus one line to the JSONL log. All connections go through trader/db.connect(), which enables WAL mode and a 15 s busy_timeout so this viewer can keep reading while the bot commits (override with TRADING_DB_WAL / TRADING_DB_BUSY_TIMEOUT_MS).

Size-based rotation: before each append, _maybe_rotate_journal renames journal.jsonl to journal.jsonl.YYYYMMDD-HHMMSS once it exceeds JOURNAL_MAX_BYTES (default 100 MB) and prunes oldest rotated siblings beyond JOURNAL_KEEP_ROTATED (default 10). Set JOURNAL_MAX_BYTES=0 to disable. The weekly reporter's load_jsonl_since walks rotated siblings alongside the live file (mtime-ordered, oldest first), so the 7-day review window always spans rotations.

After all symbols, main logs cycle_summary with action_counts, elapsed_sec, cycle_errors, failed_symbols, slowest_symbols_ms (top-5 per-symbol elapsed time — surfaces a hung enrichment source after the fact), and a compact market_regime block. Same payload appended to TRADING_METRICS_JSONL_PATH when set. main.ping_healthcheck pings HEALTHCHECK_URL (or its /fail sibling) at the end of each cycle.

9 Viewer

This FastAPI app (trader/web/app.py) is read-only. It reads SQLite for cycles/logic_json (/, /cycle/:id), Alpaca live for /positions, and the latest weekly blog at /report/latest.md (Markdown). Token-gated by TRADE_LOG_VIEW_TOKEN.

10 Weekly report and blog

Cron (e.g. Sunday, see docs/TRADING_BOT.md) runs python -m trader.weekly_review. That loads the last 7 days of journal.jsonl plus SQLite aggregates (and optional WEEKLY_HUMAN_JOURNAL_PATH / Alpaca closed orders when enabled), attaches a bot_operating_snapshot (resolved watchlist screener size, option tier caps, trail giveback %) so the reviewer interprets multi-contract option rows correctly, calls Sonnet, and writes under data/reports/: dated weekly-YYYY-MM-DD.md, LATEST_REVIEW.md (stable path for automation / GET /report/latest.md), TRADER_FEEDBACK.md (short bullets the brain may read next week), and a small JSON sidecar.

The same run also writes a human-readable blog post with SVG charts to data/reports/blog-YYYY-MM-DD.md + .charts.json. The dashboard surfaces it at /blog and /blog/{slug} — that is the only delivery channel; nothing posts externally on its own.

Hard rules baked into risk_engine.validate

  • Confidence floor: MIN_CONFIDENCE (default 0.65) — below ⇒ HOLD.
  • Position cap: MAX_POSITION_PCT (default 5% of equity) — clamped, not rejected.
  • Daily loss circuit breaker: MAX_DAILY_LOSS_PCT (default 2%) ⇒ HALT.
  • Drawdown from peak: MAX_DRAWDOWN_FROM_PEAK_PCT (default 15%) ⇒ HALT; peak tracked in risk_state.
  • Symbol cooldown: SYMBOL_COOLDOWN_HOURS (default 24h) since the last journaled SELL ⇒ HOLD.
  • Concurrency: MAX_CONCURRENT_BUYS (default 1) — no new BUY when at cap.
  • Add-to-position: MAX_ADD_TO_POSITION (default false) — second BUY on an already-held long_stock ⇒ HOLD unless set to true.
  • Options min hold: OPTIONS_MIN_HOLD_HOURS (default 0.5h) — SELL on open option before hold period ⇒ HOLD; bypass when unrealized_pct ≥ PROFIT_LOCK_PCT (default 20%).
  • Strategy allowlist: long_stock, long_call, long_put, csp, vertical_spread.
  • Symbol universe: the current cycle's watchlist (held underlyings auto-injected via WATCHLIST_INCLUDE_OPEN_POSITIONS so the bot can always SELL what it owns).
  • PDT: Alpaca daytrade_count ≥ PDT_DAYTRADE_CEILING with equity < PDT_EQUITY_FLOOR ⇒ new BUY ⇒ HOLD (pdt_ceiling).
  • Sector cap: MAX_SECTOR_NOTIONAL_PCT > 0 — block BUY if existing + new size_pct in the same sector would exceed the cap (uses snapshot sector fields).
